# 首版产品独立静态审查记录

审查日期：2026年9月12日。审查对象为`/workspace/sites/patent-intelligence/core/engine.mjs`、`core/docx.mjs`和`app/page.tsx`。依据为附件第十一节P0需求、第十二节交互要求及A02、A03、A04、A07、A09、A12、A13、A14验收建议。本次仅阅读源代码及追踪状态流转，未修改项目代码，未执行浏览器操作，未将静态推断写成已完成的运行测试。

## 一、审查意见

当前代码已经建立共享核心和完整页面流程，但仍存在三项应在交付前解决的主要缺陷。最直接的问题是自由输入的新主题能够携带旧主题检索词继续运行，并生成使用新主题标题的旧主题结果；此外，手工任务备份恢复会丢失已完成工作，损坏的本机状态也可能导致页面恢复时崩溃。这些问题分别影响主题真实性、成果恢复和主要错误处理，不能仅通过默认示例成功运行判定P0通过。以下结论基于本次读取时的代码；协作期间修改后的版本需要重新核对。

## 二、应优先修复的问题

### CR-01：自由输入新主题后直接运行会沿用旧检索策略

新主题输入与实际检索策略之间缺少一致性约束。`app/page.tsx`第39行主题输入仅调用`setTopic()`，第27行`run()`将当前旧`strategy`传入`createTask()`；`core/engine.mjs`第55行`normalizeStrategy()`先生成新主题基础策略，再由旧策略字段覆盖，并最终只更新`topic`。因此，从默认液氢主题直接输入一个无关主题后点击运行，结果仍可能来自液氢词表，而任务和报告已经写成新主题。

该问题应作为阻断项处理，因为它违反A03要求的新主题合理变化，也会误导使用者理解结果来源。页面上的示例按钮会正确替换策略，独立的更新检索词按钮也可以规避问题，但二者均不能覆盖最普通的直接输入后运行路径。建议明确记录策略绑定的主题，运行时发现主题变化便重新生成基础词组并同步展示；如需支持用户主动重用旧策略，应通过清楚的当前状态说明表达这一选择。

建议复验步骤为：先运行默认液氢示例，再只修改主题为电池液冷，直接点击运行；检查对象词、重点词、查询记录、结果和报告均切换至新主题。随后仅编辑检索词再次运行，确认人工修改得到保留。最后输入未覆盖的新主题，检查无相关样本时产生空结果并解释范围。

### CR-02：手工任务备份恢复会丢失查询、报告及人工筛选状态

完整任务备份目前只能恢复部分输入材料。`app/page.tsx`第31行`backUp()`保存了`task`、`excluded`、`notes`、`edit`和`learning`，但第32行`restore()`将任务设为`null`、排除列表设为空数组，且不恢复查询历史、报告历史或学习模式。恢复函数虽然暂时设置了`notes`，紧接着用户按提示重新运行时，第27行`run()`又清空这些筛选理由。

该问题应在宣称任务可恢复前解决，因为它会使用户以为已备份的工作在恢复后消失。恢复成功提示只说重新筛选校验，没有说明会失去任务标识、已导出版本和排除决定，入口名称却为任务备份。建议统一提供经过校验的任务恢复函数，对原数据重新规范化后保留可核对的查询历史、人工决定和报告版本；发生引用失效时单独标记相应产物，保留用户原编辑和旧报告。若首版暂只支持材料导入，应改成准确名称并明确完整任务恢复未完成。

建议复验步骤为：创建一个任务，排除一条记录、填写两条筛选理由、编辑报告、导出两版报告，再备份；清空工作区后恢复，检查任务标识、筛选条数、理由、查询历史、报告历史和用户编辑均可找到，并检查来源模式准确。恢复后重新运行不应静默删除已恢复的用户成果。

### CR-03：本机恢复数据未经完整校验，异常可越过恢复错误处理

本机状态恢复缺少能覆盖后续渲染的校验。`app/page.tsx`第23行仅检查`schema`、`dataset.records`、`strategy`和`topic`存在，随后直接将存储中的`dataset`和`task`写入状态；第25、26行在渲染期间执行`refineTask()`和`reportMarkdown()`。若存储中的任务缺少`records`、证据字段、统计字段或存在不一致引用，异常会在后续渲染中产生，无法由读取localStorage时的`try/catch`捕获。

该问题会阻断本机状态异常后的主要用户流程，属于恢复与错误处理缺陷。对于同源环境中部分写入、旧版本迁移、用户手动编辑或已损坏状态，当前页面可能无法给出重新选择示例的可操作界面。建议在提交React状态之前验证完整恢复对象并重新计算派生结果，同时保留失败备份；渲染层再提供可恢复的错误状态，避免每次打开继续载入同一损坏对象。

建议复验步骤为：分别将本机任务中的`records`删除、将一个证据ID改为无效、将策略日期改为非法值，再刷新；页面应提供具体错误与重新开始/导入备份入口，不应出现整页崩溃。该步骤是待执行验证，本次未修改浏览器存储。

## 三、影响一致性和证据使用的其他问题

### CR-04：用户提供的权利要求没有进入可阅读证据流程

权利要求字段的保存、可见性和材料范围说明存在不一致。`core/engine.mjs`第36行读取`r.claims`，第39行的证据构造却仅使用`r.evidence`或摘要；当一条合法导入记录具有标题与`claims`、缺少摘要及`evidence`时，统计会显示该记录具有权利要求，但证据列表仍为空。报告正文不输出`claims`，证据对话框第73行还固定表示完整权利要求尚未取得。

该问题影响导入材料的实际可用性，也会导致用户无法检查已经提供的内容。建议将用户权利要求文本作为有来源标记的独立证据片段，并根据实际字段显示材料范围；如果首版不支持该字段，应在导入提示和数据契约中明确，不能一边计为已有权利要求，一边不提供阅读入口。复验时使用一条只有标题、公开编号、来源和权利要求的记录，检查可见文本、证据ID、报告与统计一致。

### CR-05：外部扩展检索链接省略已设置日期条件

外部查询入口没有带上本地策略中的日期范围。`core/engine.mjs`第57行`externalSearchURL()`仅编码`queryText()`，后者只包含对象词、重点词与排除词；`from`、`to`和日期类型均未传入Google Patents。用户设置公开日期后，内部结果和报告保留该范围，而点击扩展检索将得到不同范围的外部查询。

该问题应通过准确传参或明确提示消除歧义。Google Patents不同日期字段具有不同语义，后续修改需基于官方语法验证公开日期限制；未完成核验时，可在链接前明确标注仅携带词项、日期需在外部设置。复验应直接检查生成URL与外部页面实际采用的字段，不能仅比较页面上的检索式文本。

### CR-06：单次导出使用了两次生成的报告文本

导出版本归档与实际下载文件的生成时间可能不同。`app/page.tsx`第29行先调用`saveReport(current,edit)`，它在`core/engine.mjs`第91行重新生成Markdown；但Word与Markdown下载使用的是此前`useMemo()`得到的`report`。`reportMarkdown()`内嵌当前时间，因此历史归档文本和下载文件并非同一份固定内容，之后状态更新还会使预览时间再次变化。

该问题目前主要体现为时间及可重复性差异，不应夸大为已发现正文内容丢失。建议单次导出只生成一个不可变报告对象，预览、Markdown、Word与证据JSON均由该对象派生，并把生成时间作为报告版本字段传入。复验应对下载Markdown和对应历史版本内容作字节比较，并核对Word正文中的生成时间。

### CR-07：重复证据片段可能造成重复ID和Word书签

证据规范化目前没有删除同一记录中的相同片段。`core/engine.mjs`第40行依据字段和文本生成证据ID，但仍逐条加入数组；同一记录的`evidence`中若出现两份相同字段和文本，会产生重复ID和偏大的证据计数。`core/docx.mjs`第10、12行按这些ID构造书签，重复证据行会对应相同书签标识。

该问题属于导入边界与导出可追溯性缺陷。建议在单条记录内按稳定证据ID去重，冲突时保留明确的不同定位信息，或为不同位置生成可区分ID。复验应导入含重复片段的文件，检查证据数量、引用唯一性及Word书签唯一性；本次未生成该边界文件或实际打开Word。

## 四、未发现阻断证据的部分与必要保留意见

当前核心规则在若干重要环节已经体现真实性约束。导入统一标为用户提供，快照和测试记录具有模式字段；结果统计从保留记录重新计算，空集合会给出缺少材料说明；报告中的研究问题没有直接转化为侵权或创新空白结论。证据引用校验能够检查引用是否属于当前结果，并核对文本校验值。上述为源码中可见的机制，尚不能替代网页实际操作和引用逐条核验。

Word导出源码具有基本的OOXML结构、A4页设置、中文字体、标题层级、页码和超链接关系。静态阅读未发现默认样例必然无法打开的结构错误，但本次没有运行Word渲染，也不能确认中文字体替代、长网址换行、分页和逐页版式已达标。交付仍须用实际导出文件进行打开、渲染和逐页检查，特别验证长标题、长证据ID与多页报告。

实时模型和远程数据库功能未在所阅代码中实现，现有界面明确展示规则处理和本地样本范围。该项可以作为准确披露的首版边界，不应为了填满验收表写成实时接口成功。Agent宿主是否真实注册成功及是否可以调用，本次仅看到注册代码；注册失败被静默捕获，实际宿主联调应单列未验证或提供独立证据。
