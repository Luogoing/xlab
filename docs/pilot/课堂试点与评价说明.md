# 专利情报AI工具课堂试点与评价说明

版本为1.1，编制日期为2026年9月12日。本文供拟承担试点组织、课堂观察和成果评分的人员使用，参与人员、授课安排和执行日期均待确认。

本轮试点建议验证工科学生能否依据可追溯的公开记录完成一项专利情报任务，并在新主题中独立解释检索和证据判断。首轮采用45分钟课堂方案，围绕液氢储罐压力调节方案探索开展操作，再以锂电池液冷结构检验方法迁移。本文交付任务、评分和记录方法；真人参与、课堂效果和外部合作均保持待实施状态。

一、验证目标与适用边界

本轮验证应优先回答任务能否独立完成、证据是否有效和方法能否迁移三个问题。首版面向缺少系统专利训练的工科学生，预期支持主题输入、检索策略编辑、公开记录快照或用户导入、筛选、证据阅读、方案分组、报告编辑与导出。课堂执行前，由工程负责人依据实际验收记录核对可用入口和功能；本方案中的演示步骤须在当天完成预演后使用。

比较结论应限定于相同记录条件下的阅读与整理任务。首轮建议让人工路径与产品路径使用相同公开记录及相同可见字段，人工路径使用不含系统评分、分组和结论的原始记录包，产品路径导入对应记录并执行处理。这样可以观察策略解释、证据定位和材料整理的作用；公共数据库的全网检索速度、检索召回率和付费平台替代能力均需另行设计试验。

数据来源和处理方式应在课堂中分别说明。公开记录快照表示资料在标注日期预先取得，用户导入表示参与者从允许使用的文件带入资料，实时数据表示本次任务实际访问外部数据服务，测试数据仅供工程异常验证。规则处理依据程序词项、条件和模板完成，实时模型调用需要实际服务响应，已有结果回放需要保留原生成时间。首轮建议采用公开记录快照与规则处理，主持人据当天实际状态调整措辞。

任务成果应保留材料范围及未解决问题。只有摘要或短摘录的记录，能够用于识别可见技术描述；权利要求范围、专利族关系和最新法律状态缺失时，应记录补查事项。样本中缺少某方案，仅能支持当前样本未呈现该方案的描述，研究方向还需要后续检索、文献阅读或实验验证。

二、试点组织与课前准备

首轮建议先由2至3名内部成员排查任务歧义，再邀请8至12名工科学生参加小范围试用。以上人数属于组织建议，实际邀请、报名、到场、退出和有效完成任务人数分别记录。参与者按专利使用经验分层，初学者记为E0，做过一次课程检索或类似任务者记为E1，能够独立开展常规检索者记为E2；该分层只描述本次任务经验，不用于评价专业能力。

试点安排须由实际授课方确认后落实。附件任务书提及9月底上海大学专利检索课程可能提供试用机会，当前材料未确认授课人、合作关系、日期、学生人数或设备条件。组织人应在实施前确认45分钟可用时段、电脑与浏览器、资料下载方式、课堂网络、教师与观察员角色；未落实场地时可用同一材料完成内部预演。

课前资料包应足以支持两种路径在相近条件下完成任务。组织人从项目已核验快照中选取液氢主题记录，保留来源链接、公开编号、获取时间和正文可见范围，并制作不含建议答案的人工阅读包。液氢A题与B题使用相同记录池，排序固定为公开编号顺序；锂电池迁移题使用当前3条候选公开记录构成的另一份记录包。任何主题缺少足够证据时，允许任务产出说明材料不足，禁止补写专利或预设技术事实。

预演结果应决定任务能否进入课堂。建议一名未参与开发的成员按说明试做，并由具备专利情报阅读能力的审核人确认：A题和B题各能在9分钟内形成至少一项有依据的判断，迁移题能够在8分钟内完成最小答案，资料包不存在答案标签。若两题难度或材料丰富程度差异明显，先调整题目和记录包，并保存版本；尚未完成此项预演时，A19验收状态保持待实施。

匿名编号应贯穿任务、评分和反馈记录。编号可采用P001起的顺序编码，课堂记录不需要姓名、学号、联系方式或私人研究资料。组织人开场说明记录用于产品和教学改进，参与者可以停止参与并凭匿名编号提出删除请求；成果截图对外展示或联系参与者安排后续活动时，再取得相应同意。建议原始记录仅由组织与评分人员访问，试点总结确认后30天内复核保留必要性，具体保存时间待授课方确认。

三、课堂任务与顺序控制

主任务应压缩为能够在课堂内完成的公开资料判断。液氢A题为依据给定记录，整理一种与储罐压力调节有关的执行方式，指出涉及的部件或操作并附证据；液氢B题为依据同一记录池，整理一种影响储罐压力变化的热管理方式，指出作用条件并附证据。每题均需提交一版检索策略、至少一项技术判断、对应记录编号和证据片段，以及一项仍需补查的问题；若材料不支持某项结论，应具体说明缺失字段或记录。

学生应在看到系统建议前留下自己的初始策略。每题开始后先用60秒写出技术对象、两个核心词、一个扩展词或同义词，以及一个限定条件。产品路径随后允许查看和修改系统策略，人工路径继续使用个人策略阅读原始资料。初始策略单独保存，观察员记录系统建议出现的时点，避免将复制系统文本当作独立构造能力。

顺序平衡应同时控制工具先后与题目先后。建议在经验层内按四种顺序尽量均衡分配，同一参与者均完成一次人工路径和一次产品路径。四组安排如下，人数无法被4整除时允许各组人数相差1人，并记录实际分配。交叉设计仍可能存在练习效应和知识迁移，分析时保留组别、题目和先后顺序，不把全部差异归因于产品。

迁移题应检验脱离系统建议后的独立判断。学生只获得面向锂电池液冷结构任务的3条候选公开记录和空白答题页，任务是提出检索词及组合逻辑、选择一条相关记录并解释理由、引用片段支持一个结构判断、说明一项筛选条件可能排除哪些结果。部分摘录仅记载流道或流体进出口，液体介质适用性须按实际证据判断；材料未明确时列为补查事项。此阶段关闭产品建议和通用大模型，仅允许阅读给定材料。该题反映一次活动后的即时迁移表现；长期学习保持需要另设延迟测试。

四、完成标准与评分办法

完成状态应按预先约定的交付内容判定。完整完成记为complete，至少包含主题与策略、技术判断、可定位的支持证据、补查事项及可读取的成果文件；缺少其中一项记为partial，未形成可读取成果记为not_completed，主动退出记为withdrawn。资料确实不足时，给出有效的材料不足说明、原始范围和下一步获取方式可构成合格判断，由评分人说明判定依据。

效率记录应同时保留原始时间和完成质量。开始时间以题目与资料可读、主持人宣布开始为准，结束时间以参与者提交成果为准；到9分钟尚未完成的任务记为超时截尾，elapsed_seconds填实际观察时长并将timeout设为true。系统等待、读取原文、导出和正常求助均计入任务时间，仅全班统一设备中断可以另记中断秒数并据此计算净时长；两种时长均保留。有效证据数指编号可定位且片段直接支持相应判断的不同证据，不重复计数相同片段。

效率量表采用0至4分作为辅助汇总，原始时间仍是主要比较依据。4分表示9分钟内完整完成且未获得内容提示，3分表示9分钟内完整完成且有1次内容提示，2分表示时限内部分完成或完整完成但接受2次及以上内容提示，1分表示仅留下策略或记录选择等零散成果，0分表示未提交可评价成果。单纯指明按钮位置属于操作帮助，另列次数；主动告知关键词、相关记录或结论属于内容提示，两类帮助不得合并。上述时限和分级为建议口径，预演修改后须在正式开始前冻结。

证据质量采用三个维度分别评分，每维0至4分，总分12分。来源定位维度中，0分为无来源或引用不存在，1分为只有平台名或标题，2分为公开编号和链接齐全但片段位置不清，3分为记录、链接、字段和片段可定位，4分为上述要素齐全且说明获取时间及可见材料范围。支持关系维度中，0分为关键判断无支持或与片段矛盾，1分为仅主题相关，2分为支持部分判断但存在扩大推断，3分为核心判断获得直接支持并区分归纳，4分为逐项对应且对证据冲突或不足作出合理处理。范围意识维度中，0分为将小样本写成确定的全球结论或法律结论，1分为提到限制但仍保留核心过度判断，2分为写明样本或摘要限制但缺少补查行动，3分为准确说明主要限制并给出补查步骤，4分为具体指出缺失材料可能改变哪项判断及验证方法。

迁移能力采用四个维度分别评分，每维0至4分，总分16分。主题拆解检查技术对象与要比较的结构是否具体；检索构造检查核心词、扩展词和组合关系是否合理；记录判断检查能否依据片段解释纳入或排除；范围反思检查能否说明筛选影响和证据不足。各维统一锚点为0分无有效回答，1分有相关词或结论但无理由，2分完成部分要素且存在明显缺漏，3分要素完整且理由与材料一致，4分能够解释条件变化如何影响结果并提出可执行的修正。评分人应在备注中引用答案片段，保留各维分数，避免仅存总分。

评分过程应尽量减少对路径身份的预期影响。建议由两名具备相应阅读能力的评价人独立评分，提交副本移除产品样式、路径标签和参与者身份，采用同样字段顺序；这只能降低可识别程度，不能保证完全盲评。两人任一维差异超过1分时，返回原始材料核对并形成协商分，同时保留初评分；只有一名评价人时如实记录，结论中说明缺少独立一致性检验。

五、记录模板与结果解释

随附CSV为未填报模板，表头之后不含参与者或效果数据。task_records.csv按一次参与者任务一行记录，score_records.csv按一名评价人对一项成果一行记录，feedback_records.csv按一项具体反馈一行记录。文件统一使用UTF-8带BOM编码，时间建议采用含时区的ISO 8601格式；尚未测量的数值留空，真实测得零值才填0。

任务记录应保留任务条件和异常经过。task_records.csv中的participant_id为匿名编号，experience_level为E0、E1或E2，sequence_group为G1至G4，task_code为LH_A、LH_B或BAT_TRANSFER，condition为manual、product或transfer_without_assistance。data_mode记录public_snapshot、user_import、live或test_data，inference_mode记录rules、live_model或replay。人工路径和独立迁移题未运行系统处理时，inference_mode留空，并在notes中记录未调用系统。dataset_version、query_version和product_version据实际文件填写。started_at与ended_at记录起止时点，elapsed_seconds为总时长，interruption_seconds为统一中断，net_seconds为二者之差，timeout与completion_status按本方案定义填写。

证据和帮助字段应能回到具体行为。source_open_count记录打开原始记录详情或来源页面次数，valid_evidence_count与invalid_evidence_count由评分后回填，操作帮助和内容提示分别填operation_help_count与content_hint_count。critical_error_codes填写对应错误代码，artifact_path指向匿名成果，notes记载实际障碍。建议错误代码包括E01引用不存在、E02引用不支持、E03摘要扩写为权利要求、E04样本范围扩大、E05数据或处理模式误报、E06导出遗漏、E07无法独立完成关键步骤；新增代码需在试点说明中解释。

评分和反馈记录应区分观察与个人意见。score_records.csv保留评价人匿名编号、效率分、三个证据维度分、四个迁移维度分、评分依据和是否协商；不适用的维度留空，人工与产品主任务均评分证据质量，迁移题评分迁移能力。feedback_records.csv分别记录反馈所对应的步骤、实际行为、参与者原话、观察员解释、再次使用意愿及原因，避免将观察员推断写入原话字段。再次使用、推荐和付费意愿属于不同问题，首轮以再次使用原因作为辅助信息。

结果汇总应先展示个体记录与缺失情况。建议报告实际到场及有效人数、各路径完整完成率、完整任务的中位时长与范围、有效证据数量、证据质量各维得分及迁移得分分布，同时列明超时、退出、帮助和故障。完成率分母使用实际开始相应任务的人数，退出另列；已完成任务的时长需要与未完成比例共同解释。人工与产品任务不同，个体时差只能作为描述线索，需按题目和顺序分层检查，首轮小样本不据此宣称确定因果效果。

继续投入的建议阈值应在实施前登记并接受负面结果。可将产品路径完整完成率达到80%、关键结论不存在E01或E02、证据质量中位数达到9分作为首轮改进目标，以上均为待验证阈值。若效率改善而证据质量下降，优先修复引用与提示；若证据正确但迁移题表现较弱，调整学习环节；若多数人依赖内容提示，收缩任务并改善说明。任何阈值未达到均需记录实际原因，不能通过事后删去失败者改变结果。

六、访谈提纲与改进记录

需求访谈应从参与者最近一次真实任务展开。建议在试点结束后另约10至15分钟，询问最近一次课程作业或科研准备中是否查过专利、当时需要交付什么、实际使用哪些工具、在哪一步停住、向谁求助、最终如何判断资料可靠，以及同类任务多久出现一次。未经历过专利任务的学生可描述相近的技术资料检索经历，访谈员应保留经历类型差异。

体验反馈应紧贴本次可观察操作。请参与者展示最有帮助的一步和最难理解的一步，说明是否打开原文、哪项结论仍需要补充证据、为什么修改或保留某个关键词，以及换到锂电池主题后首先做了什么。再询问下次同类任务是否会主动使用及具体原因，并记录可能继续采用的替代工具；避免通过宽泛的喜好问题推导稳定需求。

教师反馈应落实到学生表现和教学成本。建议询问本任务是否符合课程目标、哪些专利概念仍需教师讲解、评分量表是否出现歧义、学生出现何种共同错误，以及准备数据与组织试用需要多少实际时间。教师总体认可与学生独立完成情况分别记载，尚无教师参与时保留提纲，不填写意见或认可结论。

改进事项应明确关联证据和责任角色。每项问题记录对应匿名任务、出现频次、影响步骤、具体材料或截图、建议修复和验收方式；优先处理无法完成任务、来源误导和无效引用。责任角色可先填写产品、数据、工程或教学审核，具体成员与日期在团队确认后补入，避免替未确认人员承诺工作。

七、五分钟演示讲解建议

短演示应围绕一项能够现场核对的任务展开。第0至1分钟可说明：本次展示液氢储罐压力调节方案探索，目标是从给定公开记录中形成一项有依据的技术判断，并知道还需要核查什么。随后指认当前数据模式、快照获取日期和处理模式；若当天采用规则处理，讲解中明确说明该事实，不使用实时模型生成的表述。

第1至2分钟应展示学生对策略的控制。输入主题，先写自己的核心词和限定条件，再查看建议并说明增加同义词的理由。修改一个实际参与处理的条件，运行后核对结果范围；现场没有相应结果时展示空集合和调整建议，保留真实情况。

第2至4分钟应把一项判断与原始片段对应起来。选择代表记录，打开证据，指出公开编号、来源链接、片段字段和可见范围，再查看方案分组的理由。讲解时只解释片段支持的技术信息，并举出一项仍需补查的材料；此处不提前承诺分组数量或专利数量，以当天真实结果为准。

第4至5分钟应形成可带走的成果。修改报告标题或补查事项，保存后导出一种当天已验证的格式，并打开文件核对修改和引用。结束时说明网页、命令行和后续Agent调用复用核心能力的设计方向，实际可用状态依据当前工程验收记录介绍，课堂成效保持待测。

八、十二分钟演示讲解建议

完整演示的前3分钟应交代用户问题与数据条件。先说明学生需要在有限时间内了解一项技术方案、形成检索策略和研究依据，再展示当前可用入口、实际运行环境、数据模式与处理模式。指出公开记录快照的来源和获取时间，说明如何使用JSON或CSV带入相关记录，并展示可见字段；涉及实时接口或模型时，只演示已经配置并实测的能力。

第3至6分钟应完整展示策略和筛选过程。输入液氢主题，先留下个人策略，再解释系统建议；修改关键词或时间条件后重新执行，核对任务、查询版本与结果范围。抽查一条纳入记录和一条排除记录的理由，指出排序属于当前规则的相对顺序，相关性仍需人工判断。使用相同公开编号的重复记录示例时，应提前确认其属于真实记录重复导入或明确标注的测试用例。

第6至9分钟应展示证据如何进入研究材料。打开一条短摘录，核对来源和字段，再检查方案分组与结论的支持关系；资料仅含摘要时，说明当前能够阅读的内容及补充原文的入口。编辑报告并导出，打开实际文件核对标题、模式、范围、证据和补查事项，讲解以现场真实成果为依据。

第9至11分钟应说明教学评价如何开展。介绍先自行构造策略、再查看建议的学习流程，展示锂电池迁移题和空白评分表，说明45分钟课堂采用顺序平衡安排并记录时间、证据质量和独立迁移表现。所有参与人数、通过率和学习效果在实际记录产生前均按待实施处理。

第11至12分钟应明确当前边界和下一步工作。依据最新PROJECT_STATE.md和验收记录说明已运行能力、外部接口或模型的接入状态、Agent宿主联调条件和需要补充的数据。下一步优先安排独立预演和小范围学生任务测试，再根据证据决定继续投入的功能，避免将演示流畅直接推导为需求已成立。
