# 专利情报学习原型产品与技术说明

本说明适用于0.1.0原型，编制日期为2026年9月12日。功能机制依据源码核对，实际运行结果以随附验收记录为准。

首版已经形成以公开记录和规则处理为基础的专利情报学习流程，其价值需要通过学生任务表现继续验证。产品将研究主题、检索条件、公开记录、原文证据和研究说明保存在同一任务中，提供网页、命令行和有限的Agent调用入口。当前未接通实时专利数据库或语言模型，已有代码和样本用于检验可追溯整理过程，用户访谈、课堂效果与持续使用需求尚未取得真人证据。

一、目标用户与首个任务

默认用户是正在准备工科课程作业或科研开题、尚缺少系统专利训练的学生。首个任务限定为液氢储罐压力调节方案探索，学生需要从给定材料中识别加热、放气和冷却相关结构，说明判断依据，并记录尚需补查的工作条件。预期成果是一份可编辑的探索记录，包含研究问题、检索范围、代表记录、证据片段及后续问题，满足一次阅读和整理任务的需要。

当前用户困难属于待验证的产品假设。项目重点假设学生在拆解主题、补充同义词、判断记录相关性、定位原文和说明证据范围方面存在可改善空间。团队熟悉液氢主题，为首轮工程实现提供了清楚的任务边界，但专业成员的使用经验不能代表一般工科学生；课堂方案因此安排个人初始策略、人工路径比较和独立迁移题。

公开样本承担有限材料中的方案学习和迁移检查。当前数据包含5条液氢相关记录和3条锂电池冷却结构记录，快照取得日期为2026年9月12日。锂电池任务聚焦流道构成，两条记录的短摘录仅说明流道或流体进出口，液体介质适用性需继续核查；冷却、再冷凝和低温介质之间的关系也需要依据具体文献确认。样本数量均指本次选入记录，无法据此判断领域总量、市场份额或创新空白。

二、首版范围与操作流程

P0范围围绕一次完整任务组织。用户输入主题，检查对象词、重点词、排除词和公开日期范围，选择公开快照或导入JSON、CSV，然后执行筛选。结果区显示保留记录、原文证据、初步方案分组和权利要求缺失数量；用户可以取消保留某条记录并填写筛选理由，再查看报告、补充自己的判断并导出。账户、收费、组织审批和持续监控均未进入当前实现。

检索策略采用可以人工修改的词项逻辑。对象词组与重点词组分别按任一命中处理，两组之间同时满足，排除词用于去除相应命中，日期筛选可选择保留或排除日期缺失记录。匹配文本包括标题、人工中文转述及可见原文片段，排序分数按对象词命中数乘3再加重点词命中数计算；分数表示当前样本内的相对顺序，不表示真实相关概率。分类号目前仅提示用户在官方分类表核验，未自动推荐。

主题变化和条件修改会影响后续实际处理。液氢、电池主题使用预设中英文扩词，一般主题按输入词项建立初始策略；需要更具体的专业词时由用户补充。同一主题重新运行形成新查询版本，修改尚未运行时页面提示结果仍对应旧条件。无匹配记录时保留查询和资料范围，提示放宽条件或导入相关资料；外部检索链接仅打开检索入口，日期等条件需要在目标平台另行设置。

学习模式为同一工作流程增加解释和自查。页面提供扩词说明、证据范围练习及匿名反馈导出，课堂材料要求学生先保留自己的策略再查看建议。当前练习反映一次自查结果，尚未证明学习能力提高；进一步判断需结合课堂完成时间、有效证据、错误类型与独立迁移表现。教学组织和评价使用随附课堂试点包，无需新增班级后台。

三、数据与处理方式的取舍依据

首版采用公开记录快照和用户导入，是依据已取得的数据条件作出的工程选择。开发阶段已对入选公开页面进行人工核验，并验证一个已知公开编号页面可以通过终端获取；该证据支持已知文献读取，未形成从任意主题稳定调用全库检索API的证明。交付数据只保留标识、来源、必要短摘录和人工转述，后续来源接入可以继续扩展，当前主流程能够先完成资料处理和证据展示。

现有检索服务已经提供多项基础能力，首版应验证具体学习过程能否改善。Google Patents官方帮助说明结果页可下载最多前1000条CSV，实际可能更少，总数为近似值且默认折叠简单专利族。WIPO在2026年7月2日发布PATENTSCOPE自然语言辅助构造查询功能，使用时需要WIPO账户。这些事实说明查询构造和结果导出已有替代路径；本项目对策略解释、证据定位和可编辑探索记录的价值判断仍是待测假设。现有CSV导入接受项目规定字段，厂商原始导出文件的自动映射需另行验证。[Google Patents结果页帮助](https://support.google.com/faqs/answer/7049588?hl=en)；[WIPO辅助检索公告](https://www.wipo.int/en/web/patentscope/w/news/2026/patentscope-ai-assisted-search-now-available)。

正式数据接口需要在授权和实际响应条件明确后接入。EPO OPS官方说明采用REST与XML提供数据，接入需要注册凭证并处理OAuth认证。当前代码未依赖相关账户即可处理样本和导入记录，因而无需把账号申请设为全部开发的前置条件；取得授权后仍需核对字段覆盖、配额、保存条件和错误行为，再实现来源适配。竞品官网和接口说明只支持其公开规则，本轮没有竞品账户实测或报价结果。[EPO OPS说明](https://www.epo.org/en/searching-for-patents/data/web-services/ops)。

规则处理使首轮输出能够围绕可见材料逐项复核。当前筛选、分组、统计和报告模板均在本地执行，不消耗实时模型调用；自动事实使用实际证据片段，研究问题采用带引用的待验证提问。规则词表对表达变体和复杂语义的覆盖有限，可能遗漏相关记录或把相近过程归在同组，因此保留用户筛选、证据阅读和编辑入口。数据模式与推理模式分别保存，避免把公开真实记录误报为实时模型分析。

四、共用核心与数据契约

工程采用React与TypeScript界面加标准ES模块核心的结构。core/engine.mjs负责导入、规范化、策略、筛选、统计、分析、报告及恢复；core/docx.mjs负责Word文件封装。网页直接导入这些模块，cli/patent.mjs和Agent适配层调用相同能力。交付静态资源由本机HTTP脚本提供，核心处理中未引入数据库或远程任务队列；后续如确有并发和持久化需求，再依据测量结果增加服务端能力。

任务对象保存足以重现当前整理过程的关键条件。task_id标识任务，version及query_history记录查询条件和版本，dataset_scope记录载入、去重、来源和取得日期，records保存当前匹配记录，analysis关联分组与证据，report_versions保存导出文本和用户编辑。stage在当前同步处理完成时标为completed，代表这次规则运算结束；外部检索与模型并未随之执行，运行耗时也仅对应当前环境及样本。

| 对象 | 核心字段与用途 |
| --- | --- |
| 运行模式 | data_mode为public_snapshot、user_import、live或test_data；inference_mode为rules、live_model或replay。当前创建任务固定使用rules。 |
| 专利记录 | publication_number、title、source_url、retrieved_at及原始主体、日期、材料范围。权利要求、法律状态、专利族允许为空。 |
| 证据片段 | evidence_id、record_id、text、field、locator、language、translated和checksum，定位具体材料并识别文本变化。 |
| 分析与报告 | claim_id、evidence_ids、scope、limitations及报告版本，将整理内容与本次记录关联。 |

规范化以公开编号去重，并保留其他潜在关联记录。编号统一大小写并去除空格与连字符，相同编号保留首条，发现题名、来源或摘要冲突时给出核验提示；相似题名、同一申请主体或接近技术内容均不触发专利族合并。申请主体保留来源原始写法，规范化仅整理空白；统计允许同一记录涉及多个主体，因此主体计数之和可能超过记录总数，无法据此推导市场份额。

导入校验限制异常输入对课堂流程的影响。单次导入上限为2000条，文本文件大小按4×1024×1024字节判断，界面标为4 MB；JSON须为记录数组或含records数组的对象，CSV须采用UTF-8及规范表头。公开编号和标题为必填项，日期、链接、表头重复、列数和引号错误均有对应反馈。缺失内容保持空值，用户导入材料默认标为未独立核验，原始文件应由用户另行保留。

五、证据报告与本机保存

证据校验围绕引用存在和当前文本一致性开展。规范化阶段根据公开编号、字段和片段内容生成证据标识，使用FNV-1a 32位校验值识别文本变化；分析及报告检查引用是否属于本次结果，原文事实必须包含所引片段。该机制能够发现部分引用错配和文本变化，无法代替专业人员对全部技术含义的判断，也不构成来源真实性认证。无证据记录保留元数据，并提示补充正文。

方案分组依据原文片段中的结构或过程词形成。当前规则覆盖加热增压、放气与气体利用、主动制冷、换热喷淋以及冷却流道等方向，同一记录可进入多个组；无法由片段识别的记录进入待补充原文分类。组名用于组织阅读材料，不能自动认定同一技术效果或介质适用性。研究问题附带引用并要求补充工况、说明书、论文或实验依据，当前不输出自动侵权、授权前景或自由实施结论。

报告编辑与自动事实分别保存，以便读者辨认责任范围。用户可修改标题、补充背景和研究判断，报告将补充内容标明为用户编辑或待核验；筛选理由随相应记录保存。每次导出建立报告版本，保留任务和查询版本、数据与处理模式、取得时间、代表记录、证据、分组和不足。查询历史可回填条件后重跑，历史报告保留当时导出文本，避免将旧结果当作新计算。

Word导出由共用JavaScript模块直接生成可编辑的OOXML文件。core/docx.mjs把报告段落、标题、来源超链接、证据书签、页码和样式打包为DOCX，浏览器与Node命令行使用同一实现，网页生成文件后由同源服务传输；运行产品和导出Word均不需要Python。Python仅用于维护本说明等正式交付材料的文档制作与渲染检查。不同终端字体条件可能影响分页，正式对外使用的导出报告仍应在目标办公软件中检查。

本机工作区和可携带备份分别承担连续工作与跨环境接续。网页把主题、策略、载入数据、任务、筛选、编辑和学习开关写入当前浏览器的localStorage，存储不足时提示导出备份；清除浏览器数据或更换设备不会自动同步。任务备份保存完整工作区，恢复时重新规范化记录并重建当前分析，历史报告标为已有结果回放；与内置快照不一致的记录保留用户导入属性。网页备份载入上限为8 MB，报告JSON用于保存任务成果，与工作区备份用途不同。

六、运行接续与后续条件

本机演示通过交付运行包中的静态资源和Node服务入口启动。scripts/serve.mjs默认监听127.0.0.1及3000端口，并提供health状态接口；该地址只服务相应本机，不意味着用户手机或其他设备可访问。命令行接受主题、输入文件、策略文件和输出目录，生成report.md、report.docx与task.json。具体启动、依赖安装、停止和测试命令在运行交接说明中集中维护，使用前以同版本工程文件核对。

Agent层已经提供有限工具实现，宿主联调需要单独记录。adapters/agent.mjs提供build_patent_strategy与explore_patent_records，后者接收明确传入的记录并返回任务、证据和Markdown；mcp-stdio.mjs实现初始化、工具列举和工具调用。网页还在环境支持document.modelContext时注册任务入口。协议实现和测试客户端只能证明相应调用路径，DSH或其他实际宿主的安装、授权及交互仍需在目标环境验证，未确认宿主名称不影响核心继续复用。

实时数据与实时模型应在明确收益后分别接入。数据侧先获得适用授权，用少量已知编号验证字段、原文、错误处理和范围标记，再增加主题查询；模型侧先明确提供方、输入资料权限和单次成本，再验证结构化输出、引用校验、超时和失败反馈。后续只有真实执行相应服务的任务才能写入live或live_model，失效时继续显示可用的导入与规则路径，并保留失败事实。

下一阶段应以独立复现和学生任务表现为依据。启动、跨主题、导入、筛选、引用、恢复和导出的测试结果由实际日志确定；课堂人数、时间及效果保持待落实状态。用户尚未授权公开发布，站点、仓库、应用市场和对外展示材料需要在具体内容可审查后另行确认。
